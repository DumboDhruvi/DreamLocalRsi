# Dream-RSI Coding Harness

A general-purpose coding-agent orchestration and recursive self-improvement layer inspired by the research paper:

> **"Dream-RSI: Recursive Self-Improvement through Evolving Worlds"**  
> Tong Zheng et al., arXiv:2609.14858 (September 14, 2026).  
> https://arxiv.org/abs/2609.14858

---

## 1. Core Concept

Standard LLM coding agents are constrained by expensive, slow, and non-deterministic agent calls during online exploration. Testing which exploration decisions work best (e.g. broad root branching vs. deep leaf refinement, test-first vs. code-first, early stopping) normally requires thousands of real LLM invocations.

**Dream-RSI solves this through an explicit Replay Loop:**

```
ONLINE DISCOVERY
       ↓
DISCOVERY TREE (trajectories & test results recorded in SQLite)
       ↓
REPLAY SIMULATOR (deterministic replay without calling coding LLMs)
       ↓
OFFLINE POLICY DREAMING (evaluating candidate policies on recorded trees)
       ↓
POLICY SELECTION (monotonicity guarantee via Dream-RSI objective V)
       ↓
NEW ONLINE DISCOVERY (redeployed with improved exploration policy)
```

---

## 2. Dream-RSI Mathematical Formulation

### Replay Objective $V$ (Equation 1)
For a candidate exploration policy $\pi$ evaluated on an empirical discovery tree $\mathcal{T}$:

$$V(\pi, \mathcal{T}) = \max_{n \in \text{revealed}} \text{score}(n) - \beta_1 \cdot \text{revealed\_attempts} + \beta_2 \cdot \text{parallelism}$$

where:
$$\text{parallelism} = \frac{\text{revealed\_attempts}}{\max(1, \text{decision\_rounds})}$$

- **$\beta_1$** (default: `0.01`): Cost/efficiency penalty per revealed attempt.
- **$\beta_2$** (default: `0.01`): Bonus for effective concurrent worker allocation.
- **Monotonicity Guarantee**: The current baseline policy $\pi_{\text{curr}}$ is always candidate #0. A candidate policy $\pi_{\text{new}}$ is adopted only if:
  $$V(\pi_{\text{new}}) - V(\pi_{\text{curr}}) \ge \Delta_{\text{margin}}$$
  This ensures the system never replaces an exploration policy with one that regresses on historical experience.

## 4. Quickstart & Commands

### Installation
Install dependencies in editable mode:
```bash
pip install -e .
```

### Running Tests
Execute the full test suite (27 unit & integration tests):
```bash
python3 -m pytest tests/ -v
```

### CLI Usage

1. **Initialize workspace & database:**
   ```bash
   dream-rsi init
   ```

2. **Run online exploration on a task:**
   ```bash
   dream-rsi run --task "Fix bug in authentication module" --agent mock --evaluator pytest
   ```

3. **Inspect the discovery tree:**
   ```bash
   dream-rsi tree
   ```

4. **Run offline dreaming to evolve an improved exploration policy:**
   ```bash
   dream-rsi dream --candidates 16 --margin 0.001
   ```

5. **View system status and active policy:**
   ```bash
   dream-rsi status
   ```

6. **View highest scoring attempt:**
   ```bash
   dream-rsi best
   ```

7. **Run baseline benchmarks (Single-Agent, Best-of-N, Fixed, Adaptive UCB, Dream-RSI):**
   ```bash
   dream-rsi benchmark
   ```

8. **Export discovery trees to JSON:**
   ```bash
   dream-rsi export -o discovery_trees.json
   ```

## 5. End-to-End Self-Improvement Demonstration

The integration test in [`tests/test_integration.py`](file:///home/dumbo/rsi_demo/tests/test_integration.py) validates the entire self-improvement cycle:

1. **Round 1 (Online Exploration)**: Initial baseline policy explores a project with failing unit tests, building an initial tree.
2. **Offline Dreaming**: The Replay Simulator replays the recorded tree across 12 candidate exploration policies without invoking any coding model.
3. **Monotonic Selection**: The policy selector evaluates candidate replay scores $V$, guarantees non-regression, and selects an improved exploration configuration.
4. **Round 2 (Online Rollout)**: The improved policy drives the next online rollout, achieving a 1.0 (100% pass) score.

## 7. Model Context Protocol (MCP) Integration

Dream-RSI is designed to run not only as a CLI tool and Python library, but also as an **MCP (Model Context Protocol) Server**, allowing AI assistants (Antigravity, Claude Desktop, Cursor, VS Code) to call the discovery harness directly.

### Exposed MCP Tools

| Tool Name | Description |
| :--- | :--- |
| `dream_rsi.start_task` | Launches online exploration on a target coding problem with automated sandboxing. |
| `dream_rsi.get_tree` | Inspects the active discovery tree, branch hierarchy, and node scores. |
| `dream_rsi.get_best_attempt` | Retrieves the highest-scoring attempt and the corresponding patch/diff. |
| `dream_rsi.run_dreaming` | Triggers offline replay dreaming across historical discovery trees to evolve the exploration policy. |
| `dream_rsi.benchmark` | Runs a comparative benchmark against baseline exploration strategies. |

### Configuration Example (`mcp_config.json`)

To enable Dream-RSI as an MCP server in your AI coding assistant:

```json
{
  "mcpServers": {
    "dream-rsi": {
      "command": "python3",
      "args": ["-m", "dream_rsi.cli", "mcp"],
      "env": {
        "PYTHONPATH": "."
      }
    }
  }
}
```

## 8. Limitations & Scope

- **Model Replacement**: The system optimizes the *exploration policy* (branching, depth, worker allocation, diversity, stopping), while keeping the underlying coding model replaceable and non-fine-tuned.
- **Deterministic Replay**: The replay simulator uses empirical histories; novel unseen branches during offline dreaming evaluate through recorded tree trajectories.
